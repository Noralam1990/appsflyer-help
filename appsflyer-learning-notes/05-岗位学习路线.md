# 按岗位学习路线

## 新手通用路线

目标：能听懂团队讨论，不被 dashboard 和术语淹没。

1. 先学 attribution：organic / non-organic、install、lookback window、click/view、SRN。
2. 再学 link：OneLink、single-platform link、`pid`、`c`、`af_adset`、`af_ad`。
3. 再学事件：in-app events、revenue、currency、CUID、S2S。
4. 再学报表：Overview、Activity、Events、Cohort。
5. 最后学专项：SKAN、ROI360、Protect360、Audiences、Data Locker。

你学完应该能回答：

- 这个 install 为什么归给这个渠道？
- 为什么 AppsFlyer 和 Meta/Google/商店不一样？
- 为什么 LTV 和 Activity 数字不一样？
- 为什么 iOS SKAN 数据慢且粗？
- 为什么事件名错了会影响渠道优化？

## 增长 / UA 路线

先掌握：

- AppsFlyer attribution model。
- Link structure and parameters。
- OneLink onboarding / create links。
- Partner Integrations / set up integrated partner。
- SRNs。
- Overview、Events、Cohort。
- SKAN Conversion Studio、SKAN Dashboard、SSOT。
- ROI360 cost、ad revenue、store revenue。
- Protect360 dashboard 和 raw data。

日常工作清单：

- 开新渠道前：确认 partner 是否在 Marketplace、需要哪些权限、是否支持 cost、SKAN、deep linking、postbacks。
- 上 campaign 前：确认 link 参数、campaign 命名、geo、OS、retargeting 标记、deep link 参数。
- 优化时：不要只看 CPI，看 cohort ROI、revenue、retention、event conversion、fraud。
- iOS campaign：同时看 SKAN、SSOT、传统 dashboard，理解延迟。
- 对账时：先确认渠道是 SRN 还是普通 link partner。

## 产品经理路线

先掌握：

- 用户旅程和 OneLink。
- Deep linking / deferred deep linking。
- In-app events taxonomy。
- Funnel、conversion、engagement events。
- Audiences。
- Activity、Events、Cohort。
- Incrementality 的基本思想。

你要负责的关键决策：

- 哪些事件代表用户真正激活？
- 新用户点击链接后应该去商店、落地页、App Clip 还是 app 内页？
- 老用户点击后进入哪个具体页面？
- 注册、购买、订阅、退款、广告展示怎么定义？
- 哪些用户适合再营销，哪些需要排除？

产品最容易踩坑：

- 事件命名随版本变化。
- 新老用户路由逻辑没有定义清楚。
- 只设计页面体验，没有设计 attribution / deep link 参数。
- 把“发生次数”和“发生用户数”混为一谈。

## 数据分析路线

先掌握：

- LTV vs Activity。
- Overview、Activity、Events、Cohort 口径。
- Raw data reporting。
- Data Locker。
- Pull API / Push API。
- SSOT Data Locker。
- User-level data retention。
- ROI360 cost/revenue。
- Protect360 raw data。

推荐建模顺序：

1. 建 install / event 明细表。
2. 建 campaign hierarchy 维表。
3. 建 cost 表。
4. 建 revenue 表。
5. 建 cohort 聚合表。
6. 加入 fraud 调整表。
7. iOS 单独加入 SKAN / SSOT 表。
8. Web / cross-platform 作为独立域接入，再做 product line 汇总。

数据分析避坑：

- 不要把 postback arrival date 当 install date。
- 不要混用 app timezone 和 UTC。
- 不要把 raw data retention 当长期数仓。
- 不要忽略 partner restrictions。
- 不要把 SKAN 和 deterministic attribution 直接相加。

## 开发工程师路线

先掌握：

- Android / iOS SDK install、integrate、test。
- In-app events。
- Conversion data。
- Unified Deep Linking。
- Privacy-preserving SDK methods。
- S2S events API。
- Purchase / subscription validation。
- Ad revenue SDK API。
- iOS postback copies。

开发交付清单：

- SDK 初始化可测试。
- Dev key / app ID 配置正确。
- 首次打开上报成功。
- 事件名和参数按数据字典实现。
- Revenue 只传数字，currency 用 ISO 4217。
- CUID 设置时机明确。
- Deep link listener 能处理 `deep_link_value` 和自定义参数。
- ATT、anonymize、sharing filter、isStopped 等隐私方法调用时机明确。
- S2S 事件有去重、重试、必要 ID 和错误监控。
- SDK release notes 在每次发版前复查。

## iOS / SKAN 专项路线

先掌握：

- ATT 和 IDFA。
- AppsFlyer iOS SDK。
- SKAN Conversion Studio。
- Apple SKAdNetwork 4 postback 和 conversion value 文档。
- SSOT。
- AAP。
- iOS 15+ postback copy。

专项交付清单：

- SDK 版本满足 SKAN 4 / ad revenue / privacy 需求。
- Conversion Studio schema 有业务 owner。
- Window 1/2/3 的事件触发时间分布经过数据验证。
- postback copy 是否配置清楚。
- SKAN partner list / ad network 支持情况确认。
- Null CV、coarse CV、fine CV 预期有监控。
- SKAN dashboard 和 SSOT 报表有 BI 解读规范。
