# AppsFlyer 术语速查

## 基础归因术语

| 术语 | 人话解释 | 容易混淆点 |
|---|---|---|
| MMP | Mobile Measurement Partner，第三方归因和营销衡量平台 | 不是广告平台本身，而是帮你统一衡量不同渠道 |
| Attribution | 判断用户安装、打开、再营销行为应该归功于哪个来源 | AppsFlyer、广告平台、商店、SKAN 可能各有口径 |
| Non-organic | 用户在安装前有可归因广告触点 | 不等于“付费一定真实有效”，还要看 fraud 和成本收入 |
| Organic | AppsFlyer 没找到可归因广告触点 | 不一定是自然搜索，也可能是归因窗口外或数据缺失 |
| Install | AppsFlyer 里通常在首次打开 app 后记录 | 渠道可能按点击或商店下载时间计算，导致差异 |
| Re-engagement | 老用户被再营销带回 app | 不是新安装 |
| Re-attribution | 曾经安装过/沉默后重新被归因 | 需要看 inactivity window 和再归因规则 |
| Lookback window | 广告触点能被归因的有效期 | 点击和曝光窗口不同，SRN 也可能有自己的规则 |
| LTV | 从安装/归因后累计到现在的用户价值 | 不等于某一天实际发生的行为 |
| Activity date | 行为实际发生的日期 | 常用于 DAU、sessions、当天事件、当天收入 |
| Cohort | 按安装/归因时间分组的一批用户 | 用来看生命周期表现，不是当天流水 |

## 链接和参数

| 参数/概念 | 作用 | 注意 |
|---|---|---|
| `pid` | Media source，媒体源/渠道标识 | 集成渠道的 `pid` 不要随意改 |
| `c` | Campaign 名称 | 建议建立命名规范 |
| `af_c_id` | Campaign ID | 比 campaign name 更适合稳定 join |
| `af_adset` / `af_adset_id` | 广告组名称 / ID | 影响下钻粒度 |
| `af_ad` / `af_ad_id` | 广告/素材名称 / ID | 创意分析常用 |
| `af_siteid` | Publisher / site ID | 排查 fraud 和渠道质量很重要 |
| `af_sub1`-`af_sub5` | 自定义扩展参数 | 先定义口径再使用，避免变成垃圾字段 |
| `af_click_lookback` | 点击归因窗口 | 支持小时或天，默认通常不是你业务的唯一答案 |
| `af_viewthrough_lookback` | 曝光归因窗口 | 一般短于点击窗口 |
| `is_retargeting=true` | 标记再营销链接 | 不加可能被当成 UA |
| `deep_link_value` | 深链目标值 | 开发需要在 app 内实现对应路由 |
| `af_dp` | URI scheme fallback | Universal Links / App Links 失败时可能用到 |
| `af_web_dp` | 桌面或 web fallback URL | 桌面点击可能不记录为移动点击，需看 OneLink 限制 |

## 报表口径

| 报表 | 回答的问题 | 常见用途 |
|---|---|---|
| Overview dashboard | UA / retargeting 的 LTV 表现如何 | 增长日常看板、媒体源/活动下钻 |
| Activity dashboard | 某段时间实际活跃和事件发生了什么 | DAU、sessions、当天收入、运营活动复盘 |
| Events dashboard | UA 带来的事件表现如何 | 看购买、注册、订阅等事件在不同渠道的 LTV |
| Cohort & Retention | 同一批用户后续表现如何 | 留存、回收周期、ROI、长线价值 |
| SKAN dashboard | iOS SKAN postback 表现如何 | iOS 14+ 聚合归因分析 |
| Raw data | 每条用户级/事件级记录 | 对账、BI、排查、CRM enrich |
| Data Locker | 自动把数据送到云存储/数仓 | 大规模 BI 管道 |
| Pull API | 主动拉取聚合或 raw 报告 | 定时报表、补数 |
| Push API | AppsFlyer 主动推送事件消息到你的 endpoint | 近实时事件流，但要管 schema 变化 |

## SKAN / iOS

| 术语 | 人话解释 | 注意 |
|---|---|---|
| ATT | Apple App Tracking Transparency，用户授权跨 app/网站 tracking | 无 IDFA 时很多 user-level 能力受限 |
| IDFA | iOS 广告标识符 | iOS 14.5+ 需要 ATT 授权 |
| SKAdNetwork / SKAN | Apple 的隐私聚合广告归因框架 | postback 由 Apple 机制控制，不是 AppsFlyer 任意生成 |
| Conversion Value / CV | 用有限数字编码用户质量 | SKAN 3 及以下主要是 0-63；SKAN 4 有 fine/coarse |
| Fine CV | 0-63 的精细值 | SKAN 4 通常只可能在第 1 个 postback 中出现，且受隐私门槛影响 |
| Coarse CV | low / medium / high | SKAN 4 低粒度值，可用于多个窗口 |
| Lock Window | 提前锁定窗口并更早触发 postback | 提早换速度，可能牺牲后续窗口内信息 |
| Crowd anonymity | Apple 用于决定 postback 可包含多少细节的隐私机制 | 低量级 campaign 可能拿不到细粒度数据 |
| SSOT | Single Source of Truth，去重整合 iOS 多归因来源 | 用于减少 ID matching、SKAN、ASA 等重复统计 |
| Null CV | postback 没有 conversion value | 常由隐私阈值或配置问题导致 |

## 收入、成本和增长

| 术语 | 人话解释 | 注意 |
|---|---|---|
| Cost | 广告成本 | 可来自 API、CSV、link 参数，优先级和粒度要确认 |
| ROI | 投入产出比 | 需要成本和收入口径同时可靠 |
| ROAS | 广告花费回报 | 常用于 UA 优化 |
| eCPI | 平均每安装成本 | 只看 eCPI 容易忽略质量 |
| Ad revenue | app 内广告带来的收入 | 不要和 IAP revenue 重复上报 |
| Store revenue | IAP / 订阅等商店收入 | 需要验证、税费、退款、平台抽成等口径 |
| Incrementality | 广告真正带来的增量 | 解决“本来就会转化的人是否被广告抢功” |
| Audiences | 按条件圈出用户并同步给渠道 | 注意用户标识、隐私、匹配率、排除列表 |

## 反作弊

| 术语 | 人话解释 | 常见信号 |
|---|---|---|
| Click flooding | 伪造大量点击，赌最后一次点击抢归因 | 点击量异常高、CVR 低、CTIT 长尾异常 |
| Install hijacking | 在真实安装即将发生时抢发点击 | CTIT 极短 |
| Device farm | 设备或模拟器批量制造安装 | 新设备比例异常、行为质量低 |
| SDK spoofing | 不真实运行 app，伪装 SDK 请求 | 需要 SDK 版本、签名、安全模块等配合防护 |
| Validation Rules | 你自定义的拦截规则 | 可按 geo、OS、收入、事件等条件拦截 |
| Post-attribution fraud | 先归因，后被识别为欺诈 | 已归因数据不会简单消失，需要对账处理 |
