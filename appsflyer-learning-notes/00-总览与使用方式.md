## 最短学习路径

第 1 天：弄懂归因和口径

- AppsFlyer install 时间通常按首次打开记录，不一定等于商店下载时间或渠道点击时间。
- 归因不是“所有平台都同一个答案”，而是“每个平台有自己的规则”。分析时先问：这是 AppsFlyer 口径、渠道口径、商店口径，还是 SKAN 口径？
- 点击通常优先于曝光，确定性方法通常优先于概率方法；具体优先级以 AppsFlyer attribution model 为准。

第 2 天：弄懂链接和事件

- `pid` 决定媒体源，`c` 决定 campaign，`af_adset` / `af_ad` 决定更细层级。
- OneLink template 是路由规则，不是给用户点击的最终链接；custom link 才是增长活动或触点中使用的链接。
- 事件体系决定后续所有优化能力。事件名、参数、收入字段、币种、CUID 一旦混乱，报表、postback、SKAN、Audiences 都会受影响。

第 3 天：弄懂报表和数据出口

- Overview 和 Events 多数是 LTV 视角：从安装 / 归因时间开始看用户后续价值。
- Activity 是行为发生日视角：看当天 DAU、session、事件、收入。
- Cohort 是生命周期分析：看同一批用户在后续小时、天、周、月的表现。
- Raw Data / Data Locker / API 是 BI 和对账的基础，但会受隐私、权限、订阅、保留期影响。

第 4 天：弄懂 iOS 和 SKAN

- SKAN 是 Apple 聚合归因，不是 AppsFlyer 私有归因。
- SKAN 4 有三个非重叠测量窗口：1-2 天、3-7 天、8-35 天。
- CV 不总是有值，Apple crowd anonymity / privacy threshold 会影响精细度。
- SSOT 是为了解决 iOS 环境里多种归因方法重复统计的问题。

第 5 天：弄懂优化和风险

- ROI360 补齐成本和收入，才能做 ROI / ROAS。
- Protect360 处理归因欺诈，但真实用户安装不会被阻止，通常只是归因或数据被拦截/标记。
- Audiences 和 Incrementality 用于人群激活和验证“广告是否真的带来增量”。

## 本知识库的可信度处理

- 只使用官方来源：AppsFlyer Help Center、Developer Hub、Glossary，以及 Apple Developer。
- 对变化快的内容，如 Partner Integrations、Web Attribution、SDK、Push API、SKAN postback copy，优先采用 2026 年仍在更新的页面。
- 对 SKAN 这类 Apple 定义的机制，使用 AppsFlyer SKAN 文档和 Apple Developer 文档交叉核查。
- 对 beta 或 closed beta 功能单独标注，不把它们当作稳定默认能力。
- 每个专题末尾都有来源提示，完整列表见 [官方来源索引](#sources)。
